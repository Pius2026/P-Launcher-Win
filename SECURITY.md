# Security Policy / 보안 정책

## Supported version / 지원 버전

Security fixes are applied to the latest source on the default branch. Older binaries and archived backups are not supported.

기본 브랜치의 최신 소스에 보안 수정이 적용됩니다. 이전 바이너리와 보관된 백업은 지원 대상이 아닙니다.

## Reporting a vulnerability / 취약점 제보

Do not disclose a vulnerability, exploit, token, personal path, or user data in a public issue.

공개 Issue에 취약점 세부 정보, 악용 방법, 토큰, 개인 경로 또는 사용자 데이터를 올리지 마세요.

Use GitHub's private vulnerability reporting feature from the repository's **Security** tab. If private reporting is not enabled, open a minimal issue asking the maintainer to provide a private contact channel, without including security details.

저장소의 **Security** 탭에서 GitHub 비공개 취약점 제보 기능을 사용하세요. 비공개 제보가 활성화되어 있지 않다면 보안 세부 정보 없이 비공개 연락 수단을 요청하는 최소한의 Issue만 작성하세요.

Include the affected version or commit, reproduction conditions, expected impact, and a safe proof of concept when possible. Remove personal data and secrets from all attachments.

가능하면 영향받는 버전 또는 커밋, 재현 조건, 예상 영향과 안전한 재현 자료를 포함하고, 첨부 파일에서는 개인정보와 비밀정보를 제거하세요.
